# 016. 课程表（#207）

- LeetCode: https://leetcode.cn/problems/course-schedule/
- 分类: 图/拓扑排序
- 开始时间: 2026-11-22 14:00
- 用时: 约 25 分钟

## 我的第一想法（未使用 AI，原文保留）

1. 为每一种课构建一个邻接表，如果该课程已在之前的链表里面存在就接着前面的来，最后发现有第一个课程在以自己为开头的链表里再度出现，则判定失败

## 复杂度

- 时间：O(v+e)
- 空间：O(v+e)

## 边界情况

- numCourses = 1, prerequisites = [] → true
- numCourses = 2, prerequisites = [] → true
- numCourses = 2, prerequisites = [[1, 0]] → true
- numCourses = 2, prerequisites = [[1, 0], [0, 1]] → false
- numCourses = 3, prerequisites = [[0, 1], [1, 2]] → true
- numCourses = 3, prerequisites = [[0, 1], [1, 2], [2, 0]] → false
- numCourses = 2000, 长链 [[1,0],[2,1],...,[1999,1998]] → true

## 卡住的地方 / 想向 AI 验证的点

- 怎样能省一点复杂度？
- 邻接表的优势在哪？

## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① 邻接表 vs 邻接矩阵

| 存储 | 空间 | 遍历某点邻居 | 判断两点相邻 |
|---|---|---|---|
| 邻接矩阵 `mat[V][V]` | **O(V²)**（2000 门课 = 400 万格） | O(V) | O(1) |
| **邻接表** `graph[v]=[...]` | **O(V+E)**（约 7000） | **O(度数)** | O(度数) |
| 边列表 | O(E) | O(E) | O(E) |

本题只需“遍历某点的邻居”（拓扑排序/DFS 都用它），不需要 O(1) 判相邻
→ 邻接表空间小几百倍、遍历还更快。**邻接矩阵只适合稠密图**。

### ② 复杂度还能省吗

不能。`O(V+E)` 是下界：每条前置关系至少看一次、每门课至少看一次。
能省的只有常数（数组代替 dict、`deque` 代替 list、避免递归）。

### ③ Kahn 判环的原理

1. 统计每个点的入度；入度为 0 的入队（没有前置课）
2. 弹出节点，把邻居入度 -1；减到 0 就入队
3. 最后 `processed == V` → 无环；否则有环

**为什么环会暴露**：环上的节点入度永远减不到 0，永远进不了队列 → `processed < V`。

### ④ DFS 三色标记 + 爆栈警告

`state`：0 未访问 / 1 正在递归栈中 / 2 已完成。
遍历邻居时遇到 `state[v] == 1` 即发现环。

⚠️ **本地实测**：本机默认递归上限 1000，2000 门课的长链会让 DFS 递归深度到 2000
→ **RecursionError**（本地 8 条用例里这条 FAIL）。

但**力扣环境的递归上限更高**，DFS 版提交后 55/55 通过（4 ms，击败 52.7%）。
结论：DFS 在力扣能过，但本地测试时要么调高 `sys.setrecursionlimit`，
要么别用深度递归——**Kahn 更稳，不依赖环境**。

### ⑤ 验证

- Kahn：8/8 全过（含 2000 长链、2000 节点 5000 边随机图 0 ms）
- DFS：7/8，长链用例 `RecursionError`（预期，见 ④）
