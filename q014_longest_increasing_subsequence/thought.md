# 014. 最长递增子序列（#300）

## 我的第一想法（未使用 AI，原文保留）

1. 使用子序列，确定“结尾值”之后再倒退，dp[i]为“以第i个元素的结尾的最长递增子数列长度”
2. 对比之下，前i个丢掉了“结尾是谁的关键信息”

## 复杂度

- 时间：O(n^2)
- 空间：O(n)

## 边界情况

- [] → 0
- [1] → 1
- [2, 2] → 1
- [7, 7, 7, 7] → 1
- [1, 2, 3, 4, 5] → 5
- [5, 4, 3, 2, 1] → 1
- [3, 1, 2] → 2
- [10, 9, 2, 5, 3, 7, 101, 18] → 4
- [1, 2, 3, 0] → 3

## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① 为什么“前 i 个”不行

`nums = [1, 100, 2, 3]`：
- 前 2 个的最优是 `1,100`，结尾是 **100**
- 放到第 3 个（2）时，`100 > 2` 接不上；而 `dp[2]` 里另一种方案 `(1)` 的信息已经丢了

**结论**：「前 i 个的最优」不记录结尾值，无法判断新元素能否接上 → 无后效性被打破。

### ② 正确状态与转移

```
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
dp[i] = max(dp[j] + 1)   对所有 j < i 且 nums[j] < nums[i]
```

- 初始化：全部为 1（每个元素自己就是长度 1）
- 答案：**`max(dp)`**

### ③ 为何不是 dp[-1]

`dp[i]` 只表示“**以 i 结尾**的最长”，最后一个元素未必属于最长序列。

反例 `[1, 2, 3, 0]`：

| i | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| nums | 1 | 2 | 3 | 0 |
| dp | 1 | 2 | 3 | 1 |

`dp[-1] = 1`，而正确答案是 `max(dp) = 3`。

### ④ 第二版：O(n log n) 的 tails + 二分

`tails[k]` = 长度为 `k+1` 的递增子序列的**最小结尾**。
对每个 x：用 `bisect_left(tails, x)` 找到第一个 `>= x` 的位置替换；若比全部大则追加。

- **不是答案序列本身**，只是让“结尾尽量小”，方便后续接上
- 严格递增用 `bisect_left`；若允许非递减则用 `bisect_right`

### ⑤ 两版复杂度

| 版本 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 朴素 DP | O(n²) | O(n) | 直观，n=2500 时约 300 万次比较 |
| tails + 二分 | **O(n log n)** | O(n) | 面试进阶答案 |
