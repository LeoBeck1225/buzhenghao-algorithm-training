## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① d 的定义与更新规则

`d` = 窗口计数 `win` 与目标计数 `need` 中**计数不相等的字符种类数**。

- 初始窗口建立后：遍历 26 个字符，`win[c] != need[c]` 就 `d += 1`
- 窗口右移时**必须成对更新，且先“移出”再“移入”**：

```
移出 out：
    if win[out] == need[out]:  d += 1    # 之前相等，移出后不等
    win[out] -= 1
    if win[out] == need[out]:  d -= 1    # 移出后反而相等（如 need[out]==0）

移入 in：
    if win[in] == need[in]:    d += 1
    win[in] += 1
    if win[in] == need[in]:    d -= 1
```

`d == 0` 说明窗口与 p 的字符计数完全一致 → 记录起点。

### ② 同一字符进出、计数没变会不会出错

不会，前提是：

1. **先出后进**（顺序不能反）
2. 每次对 `d` 都做「移出前后各判一次、移入前后各判一次」

中间状态（out 已移出、in 未移入）短暂不为 0 是正常的。
会出错的是：只更新 `in` 忘了 `out`（`d` 单调漂移）、或先 `in` 后 `out`（`out == in` 时判断错位）。

### ③ `match` 逐一比较 vs `d` 差异计数

| 方案 | 复杂度 | 优点 | 缺点 |
|---|---|---|---|
| 每次比较 26 个字符 | O(26n)，仍是 O(n) | 代码简单、不易错 | 常数略大 |
| 维护差异数 `d` | O(n)，每次 O(1) | 常数小、更快 | 更新逻辑易错，调试麻烦 |

两种都能 AC；面试可以先讲逐位比较保正确性，再说用差异计数优化常数。

### ④ 索引坑

窗口右移时移入的是 `s[i + m - 1]`，不是 `s[i + m]`（后者会越界）。
若用 `for i in range(n - m + 1)`：`i == 0` 时初始化窗口，否则移出 `s[i-1]`、移入 `s[i+m-1]`。

### ⑤ 复杂度依据

- 时间 O(n)：i 只前进 n-m+1 次，每次 O(1) 更新
- 空间 O(1)：两个长度 26 的计数数组（字符集固定）
