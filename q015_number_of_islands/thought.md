# 015. 岛屿数量（#200）

- LeetCode: https://leetcode.cn/problems/number-of-islands/
- 分类: 图/DFS
- 开始时间: 2026-11-22 13:30
- 用时: 约 30 分钟

## 我的第一想法（未使用 AI，原文保留）

1. 上下相连的1才是连通块，斜着的不算。扫描时碰到0跳过。访问1后淹掉替换成0，到边界不可扩散时岛屿计数器才+1
2. 采用BFS
3. 最后发现“发现岛屿就+1”的思路更好

## 复杂度

- 时间：O(m*n)
- 空间：O(m*n)

## 边界情况

- 空网格 → 0
- 只有水 [["0"]] → 0
- 单格陆地 [["1"]] → 1
- 一整块 [["1","1"],["1","1"]] → 1
- 两块隔开 [["1","0","1"]] → 2
- 上下两排 [["1","1","1"],["0","0","0"],["1","1","1"]] → 2

## 卡住的地方 / 想向 AI 验证的点

- 为什么要把访问过的陆地改成 '0'（或标记 visited）？ 不改会怎样？
- 我该怎么淹掉相邻的“1”？

## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① “淹”到底是什么意思

就是 **把和当前 `'1'` 连通的整片 `'1'` 全部改成 `'0'`**，让它们以后不再被扫到。
BFS 的每一步：弹出一个格子 → 看上下左右四个邻居 → 是 `'1'` 就改成 `'0'` 并入队。

### ② 为什么必须标记（不改会怎样）

1. **重复计数**：一座岛有很多 `'1'`，不标记的话每遇到一个就 +1，结果偏大
2. **死循环**：A → B → A，因为 A 还是 `'1'`，无限递归 / 队列无限膨胀

### ③ 计数时机：发现即 +1

```
for i, j:
    if grid[i][j] == '1':
        count += 1     # 发现新岛，立即计数
        flood(i, j)     # 再把整座岛淹掉
```

“BFS 结束再 +1” 结果一样，但发现即计数更直观，也不会因为中途 return 而漏计。

### ④ 关键细节：入队前就把它改成 '0'

```python
if 0 <= ni < m and 0 <= nj < n and grid[ni][nj] == "1":
    grid[ni][nj] = "0"     # 先淹，再入队
    q.append((ni, nj))
```

如果等出队时才改，同一个格子会被多个邻居**重复入队** → 队列膨胀、超时。

### ⑤ 为什么用 BFS 而不是递归 DFS

网格最大 300×300 = 9 万格。若整片是蛇形连通陆地，递归深度会到 9 万，
Python 默认递归上限 1000 → 必然 `RecursionError`。
BFS（队列）或迭代 DFS（显式栈）没有这个问题。
