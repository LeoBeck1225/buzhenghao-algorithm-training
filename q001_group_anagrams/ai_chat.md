## 001. 字母异位词分组（#49）

- 工具：DSH（Coding Agent，本地 CLI）
- 模型：deepseek-flash
- 日期：2026-11-21
- 分享链接：本地 CLI 无分享链接，故附完整对话记录

### 我的提示词 1

> 我的初稿：采用字典，key 采用原词，value 按字母的 ASCII 码储存字母，
> 输入完成后统一比较 value，输出相同的 key。
> 请帮我看这个思路有没有问题，先不要给代码。

### AI 输出摘要 1

指出 key / value 放反了：

- key 用原词时，要“按 value 找同组”就得和其他所有词比较一遍，最坏 O(n²)
- 字典的 key 唯一，本身就是分组的容器 → 应该**把特征值当 key、把词组当 value**
- 并追问：“你说的按 ASCII 码储存，是求和、排序还是计数？”（求和会碰撞）

### 我的提示词 2

> 我改成了 key 用 ASCII 顺序，比如 'abt' 'aet' 等。那复杂度怎么算？我算不来。

### AI 输出摘要 2

1. 例子举错了：`"abt"` 排序是 `"abt"`，`"aet"` 排序是 `"aet"`，两者不同组；
   应该举 `"eat"/"tea"/"ate"` → 都排序成 `"aet"`。
2. 复杂度三步法：
   - 定义 n = 词数、k = 词长
   - 每个词排序 O(k log k) + 哈希 O(1)
   - 乘起来 → 总时间 O(n·k log k)，空间 O(n·k)
3. 顺带纠正：空串排序后仍是空串，会和空串同组，不能写“不算异位词”。

### 我据此做的修改

- key 从“原词”改为“排序后的字母串”，value 存原词列表
- 例子改为 `"eat"/"tea"/"ate"` → `"aet"`
- 空串结论改为“会分到同一组”
- 补全复杂度（O(n·k log k) / O(n·k)）与 5 条边界

### 结论

思路确认可行（排序 + 哈希分组），下一步自己实现 `solution.py`，
