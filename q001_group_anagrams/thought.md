# 001. 字母异位词分组（#49）

- LeetCode: https://leetcode.com/problems/group-anagrams/
- 分类: 哈希
- 开始时间: 2026-11-21 21:20
- 用时: 约 40 分钟（含 3 轮修正）

## 我的第一想法（未使用 AI）

1. 采用字典分组：**key 用“排序后的字母串”**，**value 存同一组的原词**；
   遍历结束后把所有 value 取出来就是答案。
2. 判等条件：两个词**排序后完全相同** ⇔ 互为异位词。
   例如 `"eat"`、`"tea"`、`"ate"` 排序后都是 `"aet"`，所以分到同一组。
3. 一次遍历完成：取一个词 → 排序得到 key → 查字典 → 已有就 append，没有就新建列表。

## 复杂度

- 时间：**O(n·k log k)**
  - n = 字符串个数，k = 字符串的最大长度
  - 每个词排序 O(k log k)，共 n 个词；哈希表插入/查找平均 O(1)
- 空间：**O(n·k)**，字典里要存下所有字符（加上 n 个列表的开销）

## 边界情况

- 顺序不同但字母相同：`["abc","bca","cab"]` → 排序后都是 `"abc"` → **输出 1 组**
- 字母组成不同：`["aab","abb"]` → key 分别是 `"aab"`、`"abb"` → 分到两组
- 空串 `""`：排序后仍是 `""`，若出现会和其它空串同组（LeetCode 49 保证输入非空，实际遇不到，但概念上不能写反）
- 长度不同：排序后 key 一定不同 → 不会被误分
- 全相同的词：`["a","a","a"]` → 一组，内部有 3 个元素

## 卡住的地方 / 想向 AI 验证的点

1. **一开始把 key / value 放反了**（key 用原词、value 存特征值），
   这样找同组要两两比较，复杂度会变成 O(n²)；改成“特征值当 key”后一次遍历就够。
2. 曾想用“ASCII 码求和”当 key，但 `"ad"`(97+100=197) 与 `"bc"`(98+99=197)
   和相同却不是异位词 → 会碰撞，所以必须用**排序**或**计数**。
3. 复杂度一开始算不出来，按“外层 n 次 × 内层 k log k”推出来的。

## 修正记录（经 AI 提示后）

- 例子由 `'abt' 'aet'` 改为 `"eat"/"tea"/"ate"`（原例两组 key 不同，举错了）
- 空串结论由“不算异位词”改为“会分到同一组”
- 补全复杂度与边界

## 实现时的优化（写代码阶段）

- 最终实现没有用"排序后的字符串"当 key，改成**计数元组**：
  `cnt = [0] * 26` → `cnt[ord(ch) - 97] += 1` → `key = tuple(cnt)`
- 复杂度从 O(n·k log k) 降到 **O(n·k)**（每个词只扫一遍，不排序）
- 两种写法都正确：计数版在单词较长时更快；空间仍是 O(n·k)
- 关键点：`list` 不能当字典 key（不可哈希），所以最后要 `tuple(cnt)`
