# 001. 字母异位词分组（#49）

- LeetCode: https://leetcode.cn/problems/group-anagrams/
- 分类: 哈希
- 开始时间: 2026-11-21 21:20
- 用时: 约 20 分钟（含讨论与修正）

## 我的第一想法（未使用 AI，原文保留）

1. 采用字典，key采用ASCLL码，value按输入的字符储存，输入完成好统一比较key，输出相同的value
2. ASCLL码为按字母顺序。"eat" → 排序 → "aet"，"tea" → 排序 → "aet"，"ate" → 排序 → "aet"

## 复杂度（我的初算）

- 时间：O(k log k)，k为长度
- 空间：O(1)

## 边界情况（我的初稿）

- ["abc", "bca", "cab"] → 应该输出一组，[""] 和 [""] → 空串之间不算异位词

## 卡住的地方

- key 和 value 谁放"特征值"没想清楚，一开始写成了 key 用原词

## 经 AI 提示后的补充（这部分不是原话，单独记录）

**① 复杂度漏了外层循环**
- 每个词排序是 O(k log k)，一共 n 个词 → **O(n·k log k)**（n = 字符串个数，k = 最大长度）
- 空间不是 O(1)：字典要存所有字符 → **O(n·k)**

**② 空串结论写反了**
- 空串排序后仍是空串，会分到同一组（LeetCode 49 保证输入非空，实际遇不到）

**③ key / value 放反的后果**
- key 用原词时，要"按特征值找同组"就得两两比较，最坏 O(n²)
- 改成"特征值当 key、词组当 value"，一次遍历就够

**④ 实现时的优化**
- 最终没用排序字符串，改用 **26 长度计数元组** 当 key：
  `cnt = [0]*26` → `cnt[ord(ch)-97] += 1` → `key = tuple(cnt)`
- 复杂度从 O(n·k log k) 降到 **O(n·k)**
- `list` 不可哈希，必须 `tuple(cnt)`

**⑤ 补充的边界**
- 字母组成不同：`["aab","abb"]` → 两组
- 长度不同：排序/计数后 key 必然不同
- 全相同的词：`["a","a","a"]` → 一组 3 个元素
- 空数组：LeetCode 约束保证 `strs.length >= 1`
