# 008. 二叉树的层序遍历（#102）

- LeetCode: https://leetcode.cn/problems/binary-tree-level-order-traversal/
- 分类: 二叉树
- 开始时间: 2026-11-22 10:45
- 用时: 约 20 分钟

## 我的第一想法（未使用 AI，原文保留）

1. 类似于BFS的访问顺序。区别在于，如果存在兄弟节点则优先访问兄弟节点。我觉得需要一个临时队列去存储最左侧已发现但还没访问的节点地址。
2. （AI提示）每轮开始前先记下队列长度作为本层节点数，每弹出一个就把左右孩子入队

## 复杂度

- 时间：O(n)
- 空间：O(n)

## 边界情况

- [] → []
- [1] → [[1]]
- [1, 2] → [[1], [2]]
- [1, null, 2] → [[1], [2]]
- [3, 9, 20, null, null, 15, 7] → [[3], [9, 20], [15, 7]]
- [1, 2, null, 3] → [[1], [2], [3]]

## 卡住的地方 / 想向 AI 验证的点

- 使用队列是因为队列先进先出，访问完了直接出队列，而栈是先进后出
- 我一开始觉得层序“像 DLR”，想确认这个类比错在哪
- 子节点为 None 时要不要入队？入队会不会多出空层（比如出现 [] 或 None）？

## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① “像 DLR”错在哪

| | DLR（先序） | 层序 |
|---|---|---|
| 类型 | 深度优先 | **广度优先** |
| 结构 | 栈（后进先出） | **队列（先进先出）** |
| 走法 | 一条路扎到底再回退 | 一层铺完再下一层 |
| 顺序 | `1,2,4,5,3` | `1 / 2,3 / 4,5` |

若把队列换成栈，层序会退化成 DFS —— 所以“像 DLR”这个类比会让代码走偏。

### ② 措辞修正

队列里存的不是“最左侧”的节点，而是「**当前层所有已发现但还没访问的节点**」。

### ③ 子节点的 None 不要入队

```
if node.left:  queue.append(node.left)
if node.right: queue.append(node.right)
```

不判空会出两种问题：
1. 弹出 `None` 再访问 `.val` → AttributeError
2. 即便加了 `if node:` 跳过，`size` 已把 None 算进本层节点数 → 多出空层或错位

LeetCode 输入里的 `null` 只是序列化记法，树结构里就是 `None`，不存在“空节点占位”。

### ④ 本地测试要先建树

LeetCode 的 `[3,9,20,null,null,15,7]` 是**层序数组**，本地需用队列把它还原成树
（根入队，之后按顺序给每个节点分配左右孩子，`null` 表示该孩子缺失）。

### ⑤ 复杂度依据

- 时间 O(n)：每个节点入队、出队各一次
- 空间 O(n)：队列最宽时等于最大层宽（完全二叉树最后一层约 n/2）
