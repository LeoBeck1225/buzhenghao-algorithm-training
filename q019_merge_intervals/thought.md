# 019. 合并区间（#56）

- LeetCode: https://leetcode.cn/problems/merge-intervals/
- 分类: 排序
- 开始时间: 2026-11-22 14:50
- 用时: 约 15 分钟

## 我的第一想法（未使用 AI，原文保留）

1. 暴力：构建字典。如果a区间第一个数小于b区间第一个数则标记后删去。但这样时间复杂度过大
2. 采用双指针，只读取范围最靠左的和最靠右的（分别以左侧和右侧数据为准）区间数据，两个指针扫描，这样只用管一前一后两个数据的遍历。
3. 按左端点升序排列。然后维护一个当前合并区间 [start, end]，在看后面的[l,r]。左<后面的右→合并。end 必须取 max，否则遇到被包含的区间会把 end 错误地缩小

## 复杂度

- 时间：O(n log n)
- 空间：O(n)

## 边界情况

- [] → []
- [[1, 3]] → [[1, 3]]
- [[1, 4], [4, 5]] → [[1, 5]]（相接）
- [[1, 4], [2, 3]] → [[1, 4]]（完全包含）
- [[1, 4], [0, 4]] → [[0, 4]]
- [[1, 2], [3, 4]] → [[1, 2], [3, 4]]（不相交）
- [[1, 3], [2, 6], [8, 10], [15, 18]] → [[1, 6], [8, 10], [15, 18]]

## 经 AI 提示后的补充（这部分不是原话，单独记录）

### ① 判断条件的精确表述

不是“左 < 后面的右”，而是：

> **新区间的左端点 `l` ≤ 当前合并区间的右端点 `end`** → 合并

```python
if l <= merged[-1][1]:
```

**为什么是 `<=`**：`[[1,4],[4,5]]` 在 4 处相接，按定义要合并成 `[1,5]`；
用 `<` 会漏掉这种相接的情况。

### ② 右端点必须取 max

`[[1,10],[2,3]]`：若直接赋值 `merged[-1][1] = r`，区间会被缩成 `[1,3]`。
正确是 `max(merged[-1][1], r)` → `[1,10]`。

### ③ 为什么必须先排序

`[[2,3],[1,4]]` 不排序直接扫会得到 `[[2,3],[1,4]]`；排序后才是 `[[1,4]]`。
排序保证“左端点单调”，于是只需和结果里最后一个区间比较，不用回头扫。

### ④ 实现细节

`merged[-1][1] = max(...)` 是**原地修改**，`merged` 里存的是 `intervals` 里的同一 list 对象。
力扣能过；若担心副作用可写成 `merged[-1] = [merged[-1][0], max(...)]`。
